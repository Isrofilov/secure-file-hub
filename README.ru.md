# 🔐 SecureFileHub

SecureFileHub — лёгкий файловый менеджер на Python/Flask для размещения на собственном сервере. Вход защищён двухфакторной аутентификацией (TOTP), а веб-интерфейс работает быстро и не тянет за собой сторонних фреймворков.

*[English version](README.md)*

## 🔑 Возможности

- **Вход по TOTP**: код из любого приложения-аутентификатора; повторно использовать уже введённый код нельзя (защита от replay-атак)
- **Резервные коды**: необязательные коды для экстренного входа длиной 6–64 символа (буквы, цифры, дефисы), каждый срабатывает только один раз
- **Защита от перебора**: число неудачных попыток ограничено для каждого клиента (IPv6-адреса объединяются по /64) и в сумме для всех клиентов
- **Защищённое веб-приложение**: CSRF-защита всех изменяющих запросов, строгая Content Security Policy без inline-скриптов, файлы отдаются в «песочнице», безопасные cookie сессии
- **Просмотр файлов**: список и плитка, миниатюры изображений (кешируются в WebP), выбор нескольких файлов
- **Предпросмотр**: изображения, PDF, видео, аудио и текстовые файлы открываются прямо в браузере
- **Ссылки для доступа**: ссылка на файл, которая работает без входа, истекает через `SHARE_LINK_TTL_HOURS` и перестаёт действовать, как только файл заменён или удалён
- **Скачивание нескольких файлов**: выбранные файлы скачиваются одним ZIP-архивом, который собирается на лету, без временных файлов
- **Очередь загрузки**: перетаскивание, вставка из буфера обмена или выбор файлов, прогресс по каждому файлу
- **Тёмная тема** и интерфейс на **русском и английском**
- **Обход лимита Cloudflare в 100 МБ**: большие файлы загружаются через отдельный домен без проксирования
- **Docker-образ**, в котором приложение работает от непривилегированного пользователя

## 📋 Требования

- Python 3.12 или новее, рекомендуется 3.14 (для запуска без Docker; Docker-образ использует 3.14)
- Docker (необязательно)

## 🚀 Установка и запуск

### Docker

#### Вариант 1: готовый образ с Docker Hub

Создайте `docker-compose.yml`:

```yaml
services:
  securefilehub:
    image: isrofilov/secure-file-hub:latest
    ports:
      - "8000:8000"
    volumes:
      - ./uploads:/app/uploads
    environment:
      - TIMEZONE=Europe/Moscow
      - BACKUP_CODES=7fk2-9qpm-x3va,c8d1-mm4z-2k7w   # необязательно, каждый код одноразовый
      # - SECURE_COOKIES=true                        # если сайт работает по HTTPS
      # - TRUSTED_PROXIES=1                          # если перед приложением стоит прокси
    restart: unless-stopped
```

Запустите контейнер и найдите в логах QR-код для TOTP (см. [Первый запуск](#-первый-запуск)):

```bash
docker compose up -d
docker compose logs securefilehub
```

Приложение будет доступно по адресу http://localhost:8000.

#### Вариант 2: сборка из исходников

```bash
git clone https://github.com/Isrofilov/secure-file-hub.git
cd secure-file-hub
docker compose up -d --build
```

Входящий в репозиторий `docker-compose.yml` собирает образ локально и содержит самые нужные настройки.

#### Пользователь в контейнере

Приложение в образе запускается от непривилегированного пользователя с UID/GID из `PUID`/`PGID` (по умолчанию `1000`). При старте entrypoint исправляет владельца папки загрузок, так что файлы в подключённом томе принадлежат этому пользователю. При необходимости укажите `PUID`/`PGID` своего пользователя на хосте.

### Локальная установка

```bash
git clone https://github.com/Isrofilov/secure-file-hub.git
cd secure-file-hub
python -m venv venv
source venv/bin/activate  # в Windows: venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env      # необязательно, у всех настроек есть значения по умолчанию
```

Сервер для разработки:

```bash
python app.py
```

В продакшене используйте Gunicorn. Файл `gunicorn.conf.py` подхватывается автоматически (адрес, число процессов и потоков, таймауты):

```bash
gunicorn app:app
```

Файл `.env` из рабочего каталога загружается автоматически.

## 🔐 Первый запуск

Настраивать секреты не обязательно. Если `TOTP_SECRET` и `SECRET_KEY` не заданы, они генерируются один раз и сохраняются в `UPLOAD_FOLDER/.securefilehub` (файлы с секретами получают права `600`). После перезапуска или пересоздания контейнера используются те же значения, поэтому сессии и аутентификатор продолжают работать.

Когда TOTP-секрет создаётся впервые, сам секрет и QR-код выводятся в лог — только при этом первом запуске:

```
A new TOTP secret was generated and saved: XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX
Scan this QR code with your authenticator app:
[QR-код]
```

1. Установите приложение-аутентификатор (Google Authenticator, Aegis, 2FAS, Authy и т. п.)
2. Отсканируйте QR-код или введите секрет вручную
3. Войдите с помощью шестизначного кода из приложения

**Важно**: в каталоге `.securefilehub` лежат ваши секреты. Не открывайте к нему доступ и не забывайте про него в резервных копиях. Чтобы сбросить TOTP-секрет, удалите `UPLOAD_FOLDER/.securefilehub/totp_secret` и перезапустите приложение — в лог будут выведены новый секрет и QR-код. Можно и явно задать `TOTP_SECRET` (строка в base32), тогда сохранённый файл не используется.

В том же каталоге хранятся кеш миниатюр, незавершённые загрузки и список использованных резервных кодов. Скрытые файлы (имя начинается с точки) в списке файлов не показываются.

### Резервные коды

Резервные коды нужны на крайний случай, когда телефона нет под рукой. Перечислите их через запятую в `BACKUP_CODES`, например `7fk2-9qpm-x3va,c8d1-mm4z-2k7w`. Длина кода — от 6 до 64 символов: латинские буквы, цифры и дефисы.

Каждый резервный код срабатывает **только один раз**: использованные коды записываются (в виде хешей) в служебный каталог, а в логе видно, сколько неиспользованных кодов осталось. Храните коды отдельно от устройства с аутентификатором и добавляйте новые, когда старые подходят к концу.

## ⚙️ Настройки

Все настройки необязательны и читаются из переменных окружения (или файла `.env`). Пример — в [`.env.example`](.env.example).

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `UPLOAD_FOLDER` | `uploads` (`/app/uploads` в Docker) | Каталог для файлов |
| `SECRET_KEY` | генерируется и сохраняется | Ключ для подписи сессий и ссылок; не короче 32 случайных символов |
| `TOTP_SECRET` | генерируется и сохраняется | TOTP-секрет в base32 для приложения-аутентификатора |
| `BACKUP_CODES` | — | Одноразовые резервные коды через запятую (6–64 символа: буквы, цифры, дефисы) |
| `TIMEZONE` | `Europe/Moscow` | Часовой пояс для дат и имён ZIP-архивов; при неизвестном значении используется UTC |
| `IMAGE_PREVIEW_ENABLED` | `true` | Показывать миниатюры изображений |
| `MAX_UPLOAD_SIZE_MB` | `0` | Максимальный размер запроса на загрузку в МБ, `0` — без ограничений |
| `SESSION_LIFETIME_HOURS` | `12` | Сколько часов действует вход (считается от момента входа, а не от последнего запроса) |
| `SHARE_LINK_TTL_HOURS` | `24` | Сколько часов действуют ссылки для доступа |
| `SECURE_COOKIES` | `false` | Передавать cookie сессии только по HTTPS; включите, если сайт работает по HTTPS |
| `TRUSTED_PROXIES` | `0` | Число обратных прокси перед приложением; при `0` заголовки `X-Forwarded-*` игнорируются |
| `REAL_IP_HEADER` | — | Заголовок с настоящим IP клиента, например `CF-Connecting-IP` (см. ниже) |
| `LOGIN_MAX_ATTEMPTS` | `5` | Допустимое число неудачных входов с одного клиента за окно |
| `LOGIN_WINDOW_SECONDS` | `300` | Длина окна ограничения в секундах |
| `LOGIN_GLOBAL_MAX_ATTEMPTS` | `30` | Допустимое число неудачных входов со всех клиентов вместе за окно, `0` отключает общий лимит |
| `DOMAIN` | — | Основной домен для обхода лимита Cloudflare |
| `UPLOAD_DOMAIN` | — | Домен для загрузки без проксирования Cloudflare |
| `LOG_LEVEL` | `INFO` | Уровень логирования (`DEBUG`, `INFO`, `WARNING`, …) |
| `PORT` | `8000` | Порт, на котором слушает приложение |
| `WEB_CONCURRENCY` | `1` | Число процессов Gunicorn (оставьте 1, см. ниже) |
| `THREADS` | `16` | Число потоков в процессе Gunicorn |
| `PUID` / `PGID` | `1000` / `1000` | Пользователь и группа, от которых работает Docker-контейнер |

Любые другие параметры Gunicorn можно передать через `GUNICORN_CMD_ARGS`.

### Масштабирование

Ограничитель попыток входа хранит счётчики в памяти одного процесса. Оставьте `WEB_CONCURRENCY=1` (значение по умолчанию), чтобы все попытки учитывались в одном месте, а нагрузку распределяйте с помощью `THREADS` — загрузки и скачивания обслуживаются потоками.

## 🛡️ Защита от перебора

- Не больше `LOGIN_MAX_ATTEMPTS` неудачных попыток с одного клиента за `LOGIN_WINDOW_SECONDS` (по умолчанию 5 попыток за 5 минут)
- IPv6-клиенты объединяются по префиксу /64, потому что обычно весь префикс принадлежит одному узлу
- Общий лимит (`LOGIN_GLOBAL_MAX_ATTEMPTS`) замедляет атаки с множества адресов. На браузеры, из которых уже был успешный вход, он не распространяется, поэтому злоумышленник не сможет заблокировать владельцу доступ
- После успешного входа счётчик клиента сбрасывается
- Клиент определяется по настоящему IP-адресу, поэтому за обратным прокси важно правильно его настроить (см. ниже)

## 🌍 Обратный прокси

Если приложение работает за nginx, Caddy, Traefik, Cloudflare и т. п.:

- **`TRUSTED_PROXIES`** — укажите число прокси перед приложением (обычно `1`). По умолчанию `X-Forwarded-For` **игнорируется**: этот заголовок может прислать кто угодно, и если ему доверять, злоумышленник будет подставлять новый «IP» в каждую попытку и обойдёт ограничение на вход. При `TRUSTED_PROXIES=N` используется только адрес, добавленный последними N прокси, а также `X-Forwarded-Proto` и `X-Forwarded-Host`.
- **`REAL_IP_HEADER`** — брать IP клиента из заголовка, например `CF-Connecting-IP`. Работает только вместе с `TRUSTED_PROXIES` и только если приложение доступно **исключительно** через этот прокси, иначе клиенты смогут подделать заголовок.
- **`SECURE_COOKIES=true`** — включите, если сайт работает по HTTPS.

Минимальный пример для nginx:

```nginx
server {
    listen 443 ssl;
    server_name files.example.com;

    client_max_body_size 0;          # размер ограничивает MAX_UPLOAD_SIZE_MB
    proxy_request_buffering off;     # передавать загрузки потоком, без буферизации
    proxy_buffering off;             # отдавать большие файлы потоком
    proxy_read_timeout 1h;
    proxy_send_timeout 1h;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

С такой конфигурацией укажите `TRUSTED_PROXIES=1` и `SECURE_COOKIES=true`.

## ☁️ Обход лимита Cloudflare на загрузку

На бесплатном тарифе Cloudflare не пропускает запросы больше 100 МБ. Чтобы загружать файлы крупнее:

1. Создайте поддомен для загрузки, например `upload.yourdomain.com`
2. Добавьте для него DNS-запись **без проксирования** (серое облако, «DNS only») и настройте для него HTTPS
3. Укажите оба домена:

```
DOMAIN=yourdomain.com
UPLOAD_DOMAIN=upload.yourdomain.com
```

Сайт по-прежнему открывается через `DOMAIN`, а страница загрузки отправляет файлы напрямую на `UPLOAD_DOMAIN`. Такие загрузки авторизуются подписанным токеном, который действует `SESSION_LIFETIME_HOURS` часов; CORS разрешает запросы только с `https://DOMAIN`. Если оба домена совпадают, обход отключается.

## ✨ Использование

1. Откройте http://localhost:8000 (или свой домен) и войдите с помощью TOTP-кода или резервного кода
2. Переключайтесь между списком и плиткой — выбор запоминается в браузере
3. Кнопка предпросмотра открывает файл прямо в браузере; выделите несколько файлов, чтобы скачать их ZIP-архивом или удалить
4. Кнопка ссылки создаёт временную ссылку на файл
5. На странице загрузки файлы можно перетащить, вставить из буфера обмена или выбрать вручную
6. Язык и светлая/тёмная тема переключаются в шапке; для выхода нажмите кнопку выхода

## ⬆️ Обновление с версии 1.x

- `TIMEZONE` по умолчанию по-прежнему `Europe/Moscow`
- `X-Forwarded-For` больше не учитывается по умолчанию — если приложение стоит за обратным прокси, задайте `TRUSTED_PROXIES` (иначе все клиенты будут выглядеть как прокси и делить один лимит попыток)
- Резервные коды теперь одноразовые и должны состоять из 6–64 букв, цифр и дефисов
- Выход теперь выполняется POST-запросом (кнопкой в интерфейсе) и завершает **все** сессии на всех устройствах
- Старые ссылки на скачивание (`/download/...`) больше не работают — используйте ссылки для доступа
- Bootstrap, Flask-Babel, Flask-Minify и pytz удалены — переустановите зависимости из `requirements.txt`
- Переводы — обычные `.po`-файлы, которые загружаются при старте из `securefilehub/translations/<lang>/LC_MESSAGES/messages.po`; компилировать их не нужно
- Если раньше `TOTP_SECRET` не был задан, при первом запуске сгенерируется новый — отсканируйте новый QR-код из логов

## 🧩 Архитектура

- `app.py` — точка входа WSGI (`gunicorn app:app` или `python app.py`)
- `securefilehub/__init__.py` — фабрика приложения, логирование, заголовки безопасности, хелперы шаблонов
- `securefilehub/config.py` — настройки из окружения, генерация и хранение секретов
- `securefilehub/auth.py` — проверка TOTP и резервных кодов, ограничитель попыток, проверка входа
- `securefilehub/security.py` — CSRF, подписанные токены (ссылки для доступа, обход Cloudflare), CSP и заголовки
- `securefilehub/storage.py` — всё, что связано с папкой загрузок: список, сохранение, потоковый ZIP, миниатюры
- `securefilehub/i18n.py` — минимальный gettext, читающий `.po`-файлы
- `securefilehub/routes/` — blueprint'ы: `auth.py` (вход, выход, язык), `files.py` (файлы, загрузка, ссылки), `errors.py`
- `securefilehub/templates/`, `securefilehub/static/` — шаблоны Jinja, CSS, JavaScript и иконки
- `tests/` — тесты
- `Dockerfile`, `docker-entrypoint.sh`, `gunicorn.conf.py`, `docker-compose.yml` — развёртывание
